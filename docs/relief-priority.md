# 주민 구호와 현지 게임 유닛 유지비의 집행 순서

기준 커밋은 `6db12f8`(PR #23)이다. 40개 기준 파일에서 같은 이동 명령을 내린 기존 지급 경로의 누적 지급은 50년 1,850세트, 100년 1,877세트, 200년 1,880세트였다. 유닛이 자리를 옮기는 규칙과 한 세트의 비용(현지 창고 식량 1 + 도구 1)은 세 경로에서 같다.

## 비교 대상과 해석

| 경로 이름 | 이동 및 유지비 선택 | 구호와 지급 순서 |
|---|---|---|
| `move_off` | 이동만, 유지비 선택 끔 | 기존 구호 |
| `move_on` (A) | 최대 2개 표시, 기존 `annual-unit-upkeep/1` | 이동 → 지급 → 국내 구호 → 민간 배송 |
| `relief_first` (B) | 같은 표시, 선택형 `annual-unit-upkeep/2` | 이동 → 국내 구호 → 지급 → 민간 배송 |

모두 같은 생성 세계의 1년 차를 복사한다. 2년 차에 주소지 5의 두 유닛에 대해 5→7 명령을 한 번 내린다. 거부된 명령도 표본에 남긴다. B는 국내 구호의 기존 승인·예산·도로·운임을 그대로 집행한 뒤 **그 결과로 남은 각 창고**에서 지급한다. 새 순서는 처음 활성화할 때 선택해 저장한다. 이전 연도의 실제 기말 위치와 표시 인원만 이월한다. 그룹에 지급한 식량은 게임 유지비 계정에 기표되고 주민 섭취는 기존 민간 식사 원장에서 측정한다. 식량세는 현물이며 금전 예산은 도입하지 않았다.

한 지역·턴에서 표시 인원이 `n`, 지급 직전 식량과 도구가 `F,T`일 때 `f=min(n,F), t=min(n,T)`로 둔다. 완성 세트를 먼저 만드는 실제 결제 규칙에 맞춰 다음 네 정수의 합이 항상 `n`인지 검사한다.

| 수량 | 식 |
|---|---:|
| 실제 지급 | min(f,t) |
| 식량만 부족 | max(0,t−f) |
| 도구만 부족 | max(0,f−t) |
| 두 품목 모두 부족 | n−max(f,t) |

가령 2개 요청에 식량 1과 도구 1이면 1개 지급하고 나머지 1개는 두 품목 모두 부족하다. `move_off`에서는 플레이어가 표시한 수와 결제 요청이 0이다. 이동 명부는 보존된다.

## 원자료 읽기

[40개 시드의 체크포인트와 지역 원장](../examples/relief-priority-v1/study)에 시드별 JSON과 경로별 gzip JSONL을 저장한다. 각 압축 파일 첫 줄은 열 이름, 다음 한 줄은 한 연도의 32개 지역이다. 시드·경로·연도·지역으로 찾을 수 있다. 지역 0개 표시와 미관측값을 구분한다. 200년 말 이후의 연초·지급 직전 재고는 `null`이다. 차기 자료는 두 턴이 모두 끝난 뒤 비교 파일에만 붙인다.

- `marked, paid, missing_food_only, missing_tools_only, missing_both`는 요청 수와 지급 근거다. `before_*, after_*`는 실제 지급 시점 잔액, `depot_open_*, depot_close_*, next_depot_open_*`는 연간 경계, `next_before_*`는 다음 해 같은 처리 시점의 잔액이다. 끔 경로의 무지급 관측 경계는 이동 직후·구호 직전이다.
- 현물세 총징수와 순입고, 국내 창고 간 발송·입고·운임, 사업 재료·운임, 국제 원조 발송·입고·운임·취급손실, 구호의 창고 출고·가구 입고, 기존 public 배식과 도구 지출, 편도 이동비, 부패를 각각 보존한다. 취급손실은 원조 총발송에 이미 포함된다. [각 열이 읽은 원장 경로](../experiments/priority_evidence.py)
- [진단 코드](../experiments/checkout_diagnosis.py)는 결제 시점 증거를 시드 체크포인트와 다시 맞춘다. 지역의 기초 식량 + 순세수 + 국내 공공 입고 + 원조 입고를 그해 지출 전 가용 식량의 상한으로 쓴다. 이 상한도 요청에 미달했다면 그해 해당 창고의 기존 지출 순서만 바꾸어 채울 수 없는 수량을 분리할 수 있다.
- 기존 사업·원조·배식의 실제 영수증을 하나씩 되더한 민감도는 다른 거래를 고정한 산술 검산이다. 각 수치는 중첩될 수 있다. 사업 취소나 원조 중단이 경제 전체에 미치는 인과 효과는 여기서 추정하지 않는다. 같은 연초 구호 순서 대조만 실제로 재집행했다.

## 작은 실제 세계

| 시드 0, A → B | 실제 지급 | 국내 구호 식량 | 민간 식량 배송 | 주민 섭취 |
|---|---:|---:|---:|---:|
| 2년 차 지역 5→7, 유닛 1개 | 1 → 1 | 0 → 0 | 1,293 → 1,293 | 64,955 → 64,955 |
| 같은 이동, 유닛 2개 | 1 → 1 | 0 → 0 | 1,293 → 1,293 | 64,955 → 64,955 |
| 7년 차 지역 5, 유닛 2개 | 2 → 0 | 16 → 18 | 1,092 → 1,090 | 76,219 → 76,219 |
| 10년 차 지역 3, 유닛 2개 | 0 → 0 | 0 → 0 | 1,347 → 1,347 | 79,048 → 79,048 |

2년 차 목적지 창고는 식량 1·도구 3이었다. 다음 해에도 유닛 2개가 남았고 식량이 없어 새 지급은 0이었다. 7년 차에는 같은 연초의 식량 5·도구 28에서 구호를 먼저 집행하자 지급 직전 식량이 0이 됐다. 끔 경로의 국내 구호 역시 18이었다. 10년 차에는 식량 22가 남고 도구가 0이어서 순서로 지급을 바꿀 수 없었다. [단년 4개 사례의 세 경로·지역 원장·다음 턴](../examples/relief-priority-v1/case.json)

## 40개 시드의 결과

세 경로를 시드마다 같은 연초에서 200년까지 실행했다. 각 표본은 20개 세계다. 8개 작업자로 23,920회 연간 계산을 실행하는 데 629.732초가 걸렸다. 이 계산에는 모든 연도의 자동 원장 검산과 768,000개 지역·연도 행의 압축 기록이 포함된다. [실행 기록](../examples/relief-priority-v1/study/execution.json)

| 시점 | 표본 | 정책 | 누적 요청 | 지급 | 식량만 부족 | 도구만 부족 | 둘 다 부족 |
|---:|---|---|---:|---:|---:|---:|---:|
| 50 | 개발 | A / B | 1,960 | 989 / 931 | 934 / 1,003 | 24 / 13 | 13 / 13 |
| 50 | 검증 | A / B | 1,960 | 861 / 825 | 990 / 1,029 | 32 / 24 | 77 / 82 |
| 100 | 개발 | A / B | 3,960 | 994 / 936 | 2,929 / 2,998 | 24 / 13 | 13 / 13 |
| 100 | 검증 | A / B | 3,960 | 883 / 854 | 2,868 / 2,900 | 32 / 24 | 177 / 182 |
| 200 | 개발 | A / B | 7,960 | 994 / 936 | 6,929 / 6,998 | 24 / 13 | 13 / 13 |
| 200 | 검증 | A / B | 7,960 | 886 / 858 | 6,823 / 6,854 | 32 / 24 | 219 / 224 |

**51~200년의 직접 병목은 창고 식량이었다.** A의 요청 12,000개에서 지급 30개, 식량만 부족 11,828개, 도구만 부족 0개, 둘 다 부족 142개였다. 11,958개는 **기초 창고 식량·순식량세 입고·국내 창고 이송 입고·국제 원조 입고가 모두 0**인 지역·연도에 있었다. 남은 입고까지 합해도 식량이 부족한 수량은 11,960개다. 12,000개 요청 중 지급 직전 식량 부족은 11,970개였다. 두 값의 차이인 10개에 대해서만 해당 연도의 기존 지출을 보류하는 것으로 식량 부족을 줄일 여지가 있었다. 이 집계는 해당 위치의 그해 실물 수지만 다루며 과거에 다른 결정을 내렸을 때의 가상 재고를 포함하지 않는다. [지역별 영수증에서 재계산한 기간별 진단](../examples/relief-priority-v1/diagnosis.json)

구호 순서를 바꾼 B는 50년까지 누적 1,756세트, 200년까지 1,794세트를 지급했다. 51~200년만 떼면 B는 38세트로 A보다 8세트 많았다. 같은 구간에서 A의 공공사업·국제원조 지출을 해당 창고에 되더하는 단순 계산으로 회복되는 완성 세트는 각각 0이었다. A에서는 구호가 지급 후에 집행된다. 구호와의 직접 경쟁은 B의 첫 50년에서 관찰된다. 그때 B에서 실제 지출된 구호 식량·운임만 지급 시점 창고에 되더하면 총 112세트가 더 맞는다. 이 산술 상한과 A·B의 실제 누적 지급 차이 94세트는 서로 다른 값이다.

**식량이 왜 창고로 들어오지 않았는지도 징수 영수증으로 확인했다.** 기존 식량세는 민간 재고에서 `인구 + floor(인구/8)`을 보호하고 그 위의 잉여에서만 부과한다. A를 40개 시드에서 한 번 더 실행해 각 표시 지역의 민간 식량·보호선·기준 부과량·감면·미납·실징수·순입고를 대조했다. 51~200년의 12,000개 요청 중 11,966개는 보호선을 넘는 민간 식량이 없어 식량세 부과가 0이었고, 32개는 실제 순입고가 있었다. 2개는 잉여와 창고 공간이 있었지만 부과액이 0이었다. 마지막 두 건에서 정수 절삭과 다른 미부과 사유를 추가 분리하지 않았다. 이 세금 분류와 위의 창고 부족 분류는 같은 요청을 서로 다른 단계에서 센다. [식량세 영수증과 집계](../examples/relief-priority-v1/levy)

### 주민 생활과 반례

재고 이월에서도 같은 병목이 보인다. A의 51~200년 구간에서 지급 직후 식량이 0이었고 차기 지급 시점까지 관측한 표시 지역·연도는 5,949건이었다. 이 중 5,943건은 다음 지급 시점에도 식량이 0이었고 6건만 다시 입고된 식량이 남았다. 여기서는 지역·연도마다 한 번 세며, 유닛별 요청 수를 가중하지 않았다.

아래 수치는 **같은 시드의 B−A, 세계당 평균**이다. 인구는 해당 연도 말, 나머지는 해당 연도까지의 누적량이다. 민간 배송에는 식량·광석·도구가 포함된다.

|---:|---|---:|---:|---:|---:|---:|---:|
| 50 | 개발 | +5.40 | −45.60 | +117.45 | −6.55 | +3.40 | −21.90 |
| 50 | 검증 | +0.25 | −37.80 | −63.80 | +10.85 | −2.60 | −36.95 |
| 100 | 개발 | +5.50 | −61.25 | +113.25 | +50.45 | −3.10 | −38.10 |
| 100 | 검증 | −0.45 | −63.00 | −246.95 | +38.10 | −7.75 | −63.50 |
| 200 | 개발 | +5.50 | −18.85 | +480.90 | +102.10 | −3.10 | +5.40 |
| 200 | 검증 | −0.45 | −86.50 | −784.70 | +10.45 | −13.90 | −104.60 |

검증 시드의 200년 누적 주민 식량 부족은 B에서 8개 감소, 3개 증가, 9개 동일이었다. 시드 36은 구호가 1 늘어도 부족량이 1,048 늘었고 기말 인구는 283 줄었다. 시드 32는 지급 세트가 양쪽 모두 8개였지만 부족량이 720 줄었다. 시드 38은 구호 우선에서 장기 유닛 지급도 30→34세트로 늘었다. 시드 39의 누적 지급·주민 섭취·부족과 기말 인구는 동일했다. 같은 연초에 비교한 직접 효과와 달리, 이 장기 수치에는 세수·민간 배송·인구·생산이 다시 변화한 효과가 섞여 있다. 장기 경로의 각 후속 변화가 차지하는 몫은 분해하지 않았다.

지급 끔과 비교한 200년 누적 부족의 세계당 평균은 개발 A +137.90, B +240.00, 검증 A −39.40, B −28.95였다. 현금, 현물세, 기말 창고, 운임과 세 대비의 개별 시드 차이는 [민간·재정 지표 전체](../examples/relief-priority-v1/civil-summary.json)에 있다.

## 검산과 재현 명령

지역 원장 120개에서 창고 잔액을 독립 재구성했다. 지역별 식량·광석·도구 수지 2,304,000건, 구호 직전·직후 잔액 1,536,000건의 오차는 모두 0이었다. 764,160개 지역·연도의 다음 해 기초 잔액이 이월됐고, 마지막 해의 3,840건은 미관측으로 기록했다. [전체 원장 검산](../examples/relief-priority-v1/accounts.json)

PR #23의 고정 Git 원본과 40개의 공통 연초 해시, 지급 끔과 A의 50·100·200년 연간 전체 원장 해시 240개를 비교해 모두 일치했다. 그 시점의 기존 누적 카운터, 기말 재고·현금·인구도 모두 같았다. 기준 연구의 `annual_sha256`은 해당 체크포인트 한 해 원장의 해시다. 기준 파일에는 나머지 연도의 전체 원장 해시가 저장되어 있지 않다. [Git 원본과 대조한 호환성 확인서](../examples/relief-priority-v1/compat.json)

종전 PR #23의 공개 사례 6개와 시드 0·20의 200년 원자료도 원래 연구 실행기로 직접 재현했다. [기존 사례의 바이트 대조](../examples/relief-priority-v1/pr23-short-and-long.json)

세 경로 모두 40개 시드에서 새 프로세스로 200년까지 독립 반복했다. 965.841초가 걸렸고 작은 사례 비교 파일, 시드별 체크포인트 파일 40개, 압축을 푼 지역 원장 120개가 최초 실행과 일치했다. [독립 반복 확인서](../examples/relief-priority-v1/repeat.json)

최종 소스의 자동 테스트는 Python 3.12.14에서 530/530개가 278.064초에 통과했다. 초기 검증에서는 구호 지출이 0인 두 경로의 중간 원장까지 같을 것으로 잘못 기대한 테스트 1건이 실패했다. 구호의 개시 잔고는 지급 전후에 따라 달라야 하므로 해당 시험은 실제 물량·집행·기말 계정을 대조하도록 고친 뒤 다시 실행했다. [최종 전체 테스트 로그](../examples/relief-priority-v1/regression.txt)

기존 저장에서 새 순서를 쓰려면 첫 지급 선택에 `--relief-first`를 붙인다. 1년 차까지 진행한 저장을 사용한 예다.

```sh
python -m civsim.annual_game step year1.json --move 5 5 7 2 --upkeep 5 2 --relief-first --out year2.json
```
